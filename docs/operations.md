# تشغيل So7obDash

## 1. تطبيق GitHub

1. أنشئ GitHub App مخصصًا لهذا الاستخدام. إذا كانت المستودعات موزعة بين أكثر من مالك، مثل حساب شخصي ومؤسسة، فاجعل **تسجيل GitHub App** قابلاً للتثبيت لدى حسابات أخرى (`Public`). لا يلزم نشره في Marketplace، وتظل **لوحة So7obDash نفسها خاصة** بتسجيل دخول المالك، ولا تقبل إلا معرّفات التثبيت المدرجة في إعداداتها. التسجيل `Private` في GitHub يمكن تثبيته لدى مالكه فقط، والإصدار الحالي يستخدم بيانات تطبيق واحد. في كل تثبيت اختر المستودعات المقصودة فقط. راجع [خيارات إتاحة تطبيقات GitHub](https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/making-a-github-app-public-or-private).
2. ابدأ بصلاحيات القراءة فقط: `Metadata`، و`Issues`، و`Pull requests`، و`Actions`، و`Contents` عند الحاجة إلى قراءة الإصدارات أو سجل الالتزامات. لا تمنح صلاحيات كتابة أو إدارة. اختيار مستودعات التثبيت هو حد الوصول الأساسي.
3. فعّل Webhook إن كنت ستستخدم المزامنة عند الحدث. عنوانه `https://<dashboard-host>/api/webhooks/github`؛ استخدم سرًّا مستقلاً عشوائيًا من 32 خانة على الأقل، واجعل قيمة `GITHUB_WEBHOOK_SECRET` مطابقة له. اختر أحداث المصادر المعروضة مثل Issues وPull requests وWorkflow run وRelease، مع أحداث التثبيت/تغيير الوصول المتاحة للتطبيق. راجع [الأحداث والصلاحيات](https://docs.github.com/en/webhooks/webhook-events-and-payloads).
4. سجّل App ID ومعرّفات التثبيت المطلوبة. نزّل مفتاح PEM على الخادم فقط، واجعل الملف قابلاً للقراءة من حساب خدمة التطبيق لا من مستخدمي النظام الآخرين. راجع [صلاحيات تطبيقات GitHub](https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/choosing-permissions-for-a-github-app).

لا ترسل رمز GitHub أو مفتاحه إلى المتصفح. لا تستنتج خلو المستودعات من Milestones أو Projects إذا كانت الصلاحية أو نقطة الوصول غير متاحة.

## 2. تشغيل آمن

- ثبت Node.js 24. نفّذ `npm ci` ثم `npm run check` ثم `npm run build` من جذر المشروع. شغّل البناء بحساب موثوق، والتطبيق بحساب خدمة مستقل دون root.
- شغّل `npm run owner-password` تفاعليًا وانسخ قيمة `OWNER_PASSWORD_SCRYPT` الناتجة مباشرة إلى إعدادات الخدمة؛ لا تلصق كلمة المرور أو التجزئة في الدردشة أو سجل الأوامر أو مستودع الشيفرة.
- أنشئ ملف بيئة خدمة مستقلًا، مثل `/etc/so7obdash/live.env`، بصلاحية قراءة المالك فقط. استرشد بملف `.env.example` في جذر المشروع ولا تضع ملف التشغيل في المستودع. اضبط `SO7OB_MODE=live` وعنوان `PUBLIC_ORIGIN=https://<dashboard-host>` الصحيح بلا مسار أو شرطة مائلة في آخره. أبقِ `HOST=127.0.0.1` ومرّر HTTPS من الوكيل إلى المنفذ الداخلي `3086`. يمنع الجدار الناري الوصول الخارجي المباشر إلى المنفذ الداخلي.
- اضبط وكيل HTTPS بحيث يمرّر الجسم الخام وحقول توقيع GitHub إلى مسار Webhook بلا إعادة كتابة. لا تضع مسار Webhook خلف تسجيل دخول تفاعلي؛ مساره يؤمَّن بالتوقيع لا بجلسة المالك. لا تخزّن استجابات `/api/` في الكاش ولا تسجل أسرار الدخول أو أجسام Webhook.
- راجع [مثال وحدة systemd](systemd/so7obdash.service) وعدّل المسارات لتناسب تثبيت Node والخدمة. لا تبدأ الخدمة أو تفتح النطاق الخارجي قبل مراجعة الإعداد.

## 3. فحص القبول

- افتح النطاق المخصص من جلسة خاصة: يجب ألا تظهر بيانات حية قبل تسجيل الدخول. بعد الدخول، اختبر تحميل اللوحة، والمزامنة اليدوية، وتسجيل الخروج. اختبر رفض كلمة مرور خاطئة ورفض طلب Webhook بلا توقيع سليم.
- طابق عيّنة من القضايا وطلبات الدمج والاختبارات مع روابط GitHub. اختبر مستودعًا غير مصرح به، وتأكد من عدم إظهاره. جرّب انتهاء الجلسة وإعادة التشغيل. لا تعتبر رسالة نجاح المزامنة دليلاً على نجاح كل مصدر؛ افحص تفاصيل المصدر ووقت آخر تحديث.
- نموذج التشغيل يستخدم الذاكرة فقط للجلسات واللقطة. تفقد إعادة التشغيل الجلسات واللقطة؛ يعاد تحميل المصدر من GitHub. المزامنة الدورية كل 15 دقيقة، وحد صلاحية اللقطة 20 دقيقة؛ فقد التثبيت أو تغيير الوصول ينتج إبطال الذاكرة المؤقتة عند معالجة الحدث. عند تعطل GitHub تحقق من وضوح حالة التحديث/البيانات غير المتاحة؛ لا تبدّل الخدمة إلى التجربة.
- `GET /api/session` و`GET /api/bootstrap` للقراءة. `POST /api/login` و`POST /api/logout` لإدارة الجلسة، `POST /api/sync` لطلب المزامنة، و`POST /api/webhooks/github` للتحديث الموقّع. مسارات المتصفح الخاصة لا تستبدل الصلاحيات المنفصلة على GitHub.

## 4. التعامل مع عطل أو كشف سر

تحقق أولاً من وضع الخدمة، ثم من اسم المضيف وTLS، ومعرّف التثبيت والأذونات ومسار PEM والتوقيع. لا تستخدم مفتاحًا شخصيًا واسع الصلاحيات لتجاوز المشكلة. عند الاشتباه بتسرب، أوقف الوصول العام حسب الحاجة، وألغِ/بدّل مفتاح تطبيق GitHub والسر المكشوف وأعد تشغيل الخدمة لإسقاط الجلسات؛ افحص سجلات GitHub والوكيل دون إعادة نشر بيانات حساسة.

### نطاق الإنجاز
اختياري: اضبط `GITHUB_PROGRESS_MILESTONES=12345678:2,98765432:1`، بحيث يمثل الطرف الأول رقم المستودع الثابت، والثاني رقم المرحلة في GitHub. عند عدم ضبطه، أو تعذّر جلب النطاق كاملًا، لا تظهر نسبة للمستودع. لا تُحتسب طلبات الدمج، ولا البنود الملغاة أو المكررة، ولا المهام الأم بدلًا من تكرار احتساب أبنائها. لا تقيس النسبة النشر أو اكتمال المستودع ككل.
